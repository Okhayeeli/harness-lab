# Evidence E-001 — /api/v1/version returns HTML 404 on fresh instance

A later check does not change this record.

## Conditions
- Target: Gitea image `docker.io/gitea/gitea:1.22.3` (image id digest sha256:76f516a1a8c27e8f8e9773639bf337c0176547a2d42a80843e3f2536787341c6)
- Container: `harness-lab-gitea` started via `just start` on 2026-11-05
- Install state: fresh container, data volume empty, **initial setup wizard not completed**
- No authentication, no cookies, no API token
- Request issued from host loopback (same host as container)

## Request
```
curl -s -o body -w 'HTTP %{http_code}  bytes=%{size_download}  ctype=%{content_type}\n' \
     --max-time 2 http://127.0.0.1:13172/api/v1/version
```

## Observed response
```
HTTP 404  bytes=46  ctype=text/html; charset=utf-8
```
Body (verbatim, 46 bytes):
```
Not Found. <a href="/">Go to default page</a>.
```

## Target-state check
- `/api/healthz` on the same instance at the same time: `{"status":"pass","failed":0}` — Gitea process is up and healthy.
- Therefore the 404 is not a crashed service; it is routing behaviour for the API router on an uninstalled instance.

## Limit
- Covers only `/api/v1/version` on an uninstalled instance.
- Does NOT cover: other `/api/v1/*` paths, behaviour after the installer completes, behaviour with an authenticated session, behaviour against other Gitea versions.
